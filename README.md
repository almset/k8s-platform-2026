# Инструкция по тестированию на реальном кластере

Данное руководство поможет вам развернуть и проверить работу платформы на реальном Kubernetes-кластере. Следуйте шагам последовательно.

---

## Шаг 1. Подготовка окружения

1. **Проверка кластера**  
   Убедитесь, что у вас есть работающий кластер (например, собранный с помощью `kubeadm` или RKE2).  
   Файл `kubeconfig` должен быть доступен по пути, указанному в `group_vars/all.yml` (по умолчанию:  
   - `/etc/rancher/rke2/rke2.yaml`  
   - или `~/.kube/config`).

2. **Установка зависимостей**  
   На машине, с которой будет запускаться Ansible, установите необходимые пакеты и коллекции. Пример команд:

```bash
# Установка Ansible и коллекций
ansible-galaxy collection install kubernetes.core
pip install kubernetes
```

*(Актуальный список зависимостей см. в `Makefile` и `requirements.yml`)*

---

## Шаг 2. Инициализация GitOps-репозитория

1. **Создайте репозиторий** `platform-gitops` на GitHub или GitLab.

2. **Закоммитьте** в него все файлы из раздела **РЕПОЗИТОРИЙ 2** (это манифесты ArgoCD-приложений и компонентов платформы).

3. **(Рекомендуется)** Создайте тестовый Pull Request, чтобы убедиться, что CI/CD пайплайн (GitHub Actions с Syft, Grype, Trivy, Conftest) отрабатывает успешно. Это подтвердит корректность конфигураций и политик безопасности.

---

## Шаг 3. Запуск Ansible Bootstrap

Перейдите в директорию `platform-bootstrap` и выполните команду запуска:

```bash
# Пример команды (замените параметры при необходимости)
ansible-playbook site.yml -e platform_action=install -e platform_confirm=true
```

**Что произойдёт:**
- Ansible установит ArgoCD через OCI-реестр.
- Проверит, существует ли Application `platform-bootstrap`.
- Если нет – создаст его, после чего ArgoCD автоматически начнёт синхронизацию всех компонентов платформы.

---

## Шаг 4. Валидация в кластере

1. **Получите пароль администратора ArgoCD:**

```bash
kubectl -n gitops-system get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d && echo
```

2. **Настройте port-forward для доступа к веб-интерфейсу ArgoCD:**

```bash
kubectl port-forward svc/argocd-server -n gitops-system 8080:443
```

3. **Откройте браузер** по адресу `https://localhost:8080` (примите предупреждение о самоподписанном сертификате).  
   Вы увидите, как ArgoCD синхронизирует приложение `platform-components`.

4. **Проверьте установку Cilium:**  
   Убедитесь, что Hubble UI доступен (обычно по адресу `https://localhost:8080/hubble` после дополнительного port‑forward).

5. **Проверьте работу политик Kyverno:**  
   Попробуйте создать манифест `kind: Ingress` – он должен быть заблокирован политикой, запрещающей использование Ingress без явного разрешения.

---

## Шаг 5. Тестирование Platform API (Crossplane)

1. **Установите Crossplane и Composition Functions** в кластер.  
   Это можно сделать, добавив соответствующий компонент в `platform-gitops/components/crossplane` и дождавшись синхронизации через ArgoCD.

2. **Примените CRD и Composition** из раздела **РЕПОЗИТОРИЙ 3**.

3. **Создайте экземпляр ресурса `XWebApplication`** (пример манифеста приведён в репозитории).  
   Убедитесь, что Crossplane автоматически сгенерировал:
   - Deployment
   - HTTPRoute (или Ingress) согласно определению Composition.
